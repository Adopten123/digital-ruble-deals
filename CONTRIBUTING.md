# Совместная разработка

После принятия приглашения в закрытый репозиторий:

```sh
git clone https://github.com/Adopten123/digital-ruble-deals.git
cd digital-ruble-deals
```

Перед задачей прочитать README.md, AGENTS.md, docs/CONTEXT.md и docs/STATUS.md.

Для реализации первого прототипа также обязательны [TZ.md](docs/TZ.md), [ARCHITECTURE.md](docs/ARCHITECTURE.md), [API.md](docs/API.md) и [HANDOFF.md](docs/HANDOFF.md). Два разработчика работают в отдельных clone и ветках от общей базы. До параллельной реализации зафиксировать контракт и каркас; одного владельца назначать на время изменения миграций / Compose / API. Локальные БД и незакоммиченные файлы между ПК не синхронизируются автоматически.

## Цикл работы

1. Получить актуальный main.
2. Выбрать задачу из BACKLOG.md и согласовать ответственного.
3. Создать ветку feature/<название-задачи>.
4. Сделать один законченный результат и подходящие проверки.
5. Обновить STATUS.md: что сделано, как проверено, что осталось.
6. Отправить ветку и открыть pull request.

По запросу пользователя публикуем разработку небольшими законченными этапами. После проверок каждого этапа делать отдельный push; несколько коммитов, отправленных одной командой в конце всей разработки, не заменяют поэтапную публикацию. Черновики, изменение условий, документ и два согласия реализованы; далее резервирование → тестовые подписи и выплата по проверенному событию → спор / отмена и контроль целостности. У каждого этапа должны быть собственный результат, проверки и запись в STATUS.md. Новые функции сразу покрываются тестами; после сквозного расчёта расширяются системная приёмка и ручной прогон UI. Незавершённый код можно сохранять в feature-ветке с явным указанием готовности.

```sh
git switch main
git pull --ff-only
git switch -c feature/deal-model
git add <нужные-файлы>
git commit -m "feat: add deal model"
git push -u origin feature/deal-model
```

Не перезаписывать чужие изменения и не добавлять все файлы автоматически, если в папке есть временные или чужие материалы.

## Передача контекста AI-агенту

Пример сообщения:

> Прочитай AGENTS.md, README.md, docs/CONTEXT.md, docs/STATUS.md и связанные документы. Работай над выбранной задачей из BACKLOG.md. Сохрани границу эмулятора и обнови статус после фактических проверок.

Переход к другой IDE или модели не должен требовать пересказа переписки. Для незаконченной работы указать ветку, состояние и следующий конкретный шаг.
