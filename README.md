# ПоАкту — условные расчёты для МСБ

Банковский сервис оплаты по подтверждённому событию: заказчик резервирует сумму, исполнитель получает её после двустороннего подписания согласованного документа в ЭДО.

Пользователь выбрал название **ПоАкту** и стек **Go + PostgreSQL + TypeScript**. Техническое имя репозитория — `digital-ruble-deals`. Архитектура backend следует подходу go-todoapp-1; frontend конкретизирован как React / Vite. Требуемая готовность прототипа — 1 ноября 2026 года.

## Статус на 21 октября 2026 года

Реализованы Go / PostgreSQL / React, регистрация, вход / выход, серверные сессии, кабинет с учебными остатками, каталог контрагентов и черновики сделок: создание, поиск / фильтры / пагинация, карточка двух сторон и сохранённая идемпотентность. Подготовлены миграции, повторяемый bootstrap, Dockerfile / Compose и CI. Следующие этапы — согласование / версии документов, резервы, подписи, выплата по ЭДО и обнаружение вмешательства администратора. Подключения к платформе Банка России нет.

Добавлена папка исследований: вопросы, шаблоны интервью и командных обсуждений, реестр записей и контекст презентации «ПоАкту». Проведённых интервью пока нет.

Подготовлены ТЗ, контракт API и пакет передачи контекста для двух разработчиков на разных ПК. Текущий набор содержит 26 API-тестов, 24 UI-теста и setup Playwright: локально прошла 51 проверка, включая наложения / обрезание вёрстки. Предыдущий набор из 47 проверок подтверждён Linux CI на собранном Compose через nginx. Команды, результаты, границы и покрытие ТЗ — в [TESTING.md](docs/TESTING.md), самостоятельный прогон — в [MANUAL_TESTING.md](docs/MANUAL_TESTING.md). На текущем ПК Engine ограничен недоступной WSL2 / виртуализацией, поэтому локальный прогон использовал отдельную PostgreSQL вне контейнеров. [Фактический статус](docs/STATUS.md).

MVP показывает собственную логику условного расчёта на тестовых средствах. Цифровой рубль и платформа коммерческих смарт-контрактов (ПКСК) — целевая будущая интеграция.

## Основной сценарий

1. Две компании согласуют стороны, сумму, документ, условия и источник подтверждения.
2. Заказчик резервирует тестовые средства.
3. Имитатор ЭДО присылает проверяемое событие двусторонней подписи.
4. Сервис сверяет сделку, стороны, сумму и конкретную версию документа.
5. При отсутствии спора расчёт исполняется один раз; участники видят результат.

## Технический задел

По прямому указанию пользователя код и зависимости banking-system не используются. Архитектурный ориентир — [go-todoapp-1](https://github.com/Adopten123/go-todoapp-1): модули, ручная сборка зависимостей и слои HTTP / service / repository. Денежная логика и аутентификация создаются заново.

## Запуск и лицензия

Подготовленная команда локального стенда:

```sh
docker compose up --build
```

Адрес — **http://localhost:8080**. Доступы, альтернативный порт, сохранение данных и ограничения проверки контейнеров — в [RUNNING.md](docs/RUNNING.md). Сейчас работают авторизация, организации и черновики; полного платёжного демо ещё нет. Для запущенного изолированного стенда: `npm --prefix web run typecheck:e2e`, затем `npm --prefix web run test:e2e` с установленным Chromium; настройка адреса и вариант API без браузера — в [TESTING.md](docs/TESTING.md). Лицензия на распространение кода ещё не выбрана.
