# ПоАкту — условные расчёты для МСБ

Банковский сервис оплаты по подтверждённому событию: заказчик резервирует сумму, исполнитель получает её после двустороннего подписания согласованного документа в ЭДО.

Пользователь выбрал название **ПоАкту** и стек **Go + PostgreSQL + TypeScript**. Техническое имя репозитория — `digital-ruble-deals`. Архитектура backend следует подходу go-todoapp-1; frontend конкретизирован как React / Vite. Требуемая готовность прототипа — 1 ноября 2026 года.

## Статус на 22 октября 2026 года

Реализованы Go / PostgreSQL / React, авторизация, организации, учебные остатки, поиск сделок, версии условий / приватных PDF, два согласия, доработка и атомарный резерв полной суммы. Оператор работает с учебными зачислениями / списаниями через сбалансированный ledger; любое списание учитывает активные резервы. Миграции 001–005, bootstrap, Compose и CI сохраняют данные. Следующие этапы — тестовые подписи, выплата по ЭДО, спор / отмена, доставка уведомлений, экспорт и A19. Подключения к платформе Банка России нет.

Добавлена папка исследований: вопросы, шаблоны интервью и командных обсуждений, реестр записей и контекст презентации «ПоАкту». Проведённых интервью пока нет.

Подготовлены ТЗ, API и передача контекста для двух разработчиков. Текущий набор: 42 API + 47 UI + setup, **90 passed локально и в Linux CI**, 42 frontend unit-теста, Go-тесты с PostgreSQL / race в CI. Проверен сквозной путь до FUNDED и сохранение PDF, резерва, проводок и команд после перезапуска. [Отчёт резервирования и ручного UI](docs/reports/2026-10-22-deal-reserves.md): 12 PASS, один BLOCKED для Blob-viewer из-за политики браузерного инструмента. Команды / границы — в [TESTING.md](docs/TESTING.md), самостоятельная проверка — в [MANUAL_TESTING.md](docs/MANUAL_TESTING.md). На текущем ПК Docker Engine ограничен WSL2 / виртуализацией; локальные проверки используют отдельную PostgreSQL, Compose проверен Linux CI.

MVP показывает собственную логику условного расчёта на тестовых средствах. Цифровой рубль и платформа коммерческих смарт-контрактов (ПКСК) — целевая будущая интеграция.

## Основной сценарий

1. Две компании согласуют стороны, сумму, документ, условия и источник подтверждения.
2. Заказчик резервирует тестовые средства.
3. Имитатор ЭДО присылает проверяемое событие двусторонней подписи.
4. Сервис сверяет сделку, стороны, сумму и конкретную версию документа.
5. При отсутствии спора расчёт исполняется один раз; участники видят результат.

## Технический задел

По прямому указанию пользователя код и зависимости banking-system не используются. Архитектурный ориентир — [go-todoapp-1](https://github.com/Adopten123/go-todoapp-1): модули, ручная сборка зависимостей и слои HTTP / service / repository. Денежная логика и аутентификация создаются заново.

## Запуск и лицензия

Подготовленная команда локального стенда:

```sh
docker compose up --build
```

Адрес — **http://localhost:8080**. Доступы, альтернативный порт и сохранение данных — в [RUNNING.md](docs/RUNNING.md). Работают документы, согласования, резерв и учебные счета; полного платёжного демо ещё нет. Команды API / UI — в [TESTING.md](docs/TESTING.md). Лицензия на распространение кода ещё не выбрана; уведомления о PDF-зависимостях и шрифте сохранены в модуле.
