# ПоАкту — условные расчёты для МСБ

Банковский сервис оплаты по подтверждённому событию: заказчик резервирует сумму, исполнитель получает её после двустороннего подписания согласованного документа в ЭДО.

Пользователь выбрал название **ПоАкту** и стек **Go + PostgreSQL + TypeScript**. Техническое имя репозитория — `digital-ruble-deals`. Архитектура backend следует подходу go-todoapp-1; frontend конкретизирован как React / Vite. Требуемая готовность прототипа — 1 ноября 2026 года.

## Статус на 23 октября 2026 года

Реализованы Go / PostgreSQL / React, авторизация, организации, учебные остатки, поиск сделок, версии условий / приватных PDF, два согласия, доработка атомарный резерв полной суммы и две отдельные тестовые подписи после него. Оператор работает с учебными зачислениями / списаниями через сбалансированный ledger; любое списание учитывает активные резервы. Миграции 001–006 и bootstrap сохраняют данные. Две подписи переводят сделку в READY_TO_SETTLE и фиксируют одно устойчивое основание ЭДО; средства остаются в резерве. Следующие этапы — доставка / проверка ЭДО, единственная выплата с блокировками спором / отменой, доставка уведомлений, экспорт и A19. Подключения к платформе Банка России нет.

Добавлена папка исследований: вопросы, шаблоны интервью и командных обсуждений, реестр записей и контекст презентации «ПоАкту». Проведённых интервью пока нет.

Подготовлены ТЗ, API и передача контекста для двух разработчиков. Локально выполнены **103 E2E: 52 API + 50 UI + setup**, 47 frontend unit-тестов, Go-тесты с настоящей PostgreSQL, vet и сборки. Проверены две подписи, неизменность денег и сохранение фактов / исходных ответов после перезапуска. [Отчёт этапа подписей](docs/reports/2026-10-23-test-signatures.md) разделяет автоматические проверки, ручной UI и ограничения. Команды / границы — в [TESTING.md](docs/TESTING.md), самостоятельная проверка — в [MANUAL_TESTING.md](docs/MANUAL_TESTING.md). На текущем ПК Docker Engine ограничен WSL2 / виртуализацией; локальные проверки используют отдельную PostgreSQL, проверка Compose выполняется Linux CI.

MVP показывает собственную логику условного расчёта на тестовых средствах. Цифровой рубль и платформа коммерческих смарт-контрактов (ПКСК) — целевая будущая интеграция.

## Основной сценарий

1. Две компании согласуют стороны, сумму, документ, условия и источник подтверждения.
2. Заказчик резервирует тестовые средства.
3. Имитатор ЭДО присылает проверяемое событие двусторонней подписи.
4. Сервис сверяет сделку, стороны, сумму и конкретную версию документа.
5. При отсутствии спора расчёт исполняется один раз; участники видят результат.

## Технический задел

По прямому указанию пользователя код и зависимости banking-system не используются. Архитектурный ориентир — [go-todoapp-1](https://github.com/Adopten123/go-todoapp-1): модули, ручная сборка зависимостей и слои HTTP / service / repository. Денежная логика и аутентификация создаются заново.

## Запуск и лицензия

Подготовленная команда локального стенда:

```sh
docker compose up --build
```

Адрес — **http://localhost:8080**. Доступы, альтернативный порт и сохранение данных — в [RUNNING.md](docs/RUNNING.md). Работают документы, согласования, резерв, две тестовые подписи и учебные счета; полного платёжного демо ещё нет. Команды API / UI — в [TESTING.md](docs/TESTING.md). Лицензия на распространение кода ещё не выбрана; уведомления о PDF-зависимостях и шрифте сохранены в модуле.
