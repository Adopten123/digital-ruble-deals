# ПоАкту — условные расчёты для МСБ

Банковский сервис оплаты по подтверждённому событию: заказчик резервирует сумму, исполнитель получает её после двустороннего подписания согласованного документа в ЭДО.

Пользователь выбрал название **ПоАкту** и стек **Go + PostgreSQL + TypeScript**. Техническое имя репозитория — `digital-ruble-deals`. Архитектура backend следует подходу go-todoapp-1; frontend конкретизирован как React / Vite. Требуемая готовность прототипа — 1 ноября 2026 года.

## Статус на 25 октября 2026 года

Реализованы Go / PostgreSQL / React, авторизация, организации, учебные остатки, поиск сделок, версии условий / приватных PDF, два согласия, доработка, атомарный резерв полной суммы и две отдельные тестовые подписи после него. Оператор работает с учебными зачислениями / списаниями через сбалансированный ledger; любое списание учитывает активные резервы. Миграции 001–009 и bootstrap сохраняют данные. После двух тестовых подписей worker доставляет событие ЭДО с HMAC; точная проверка освобождает собственный резерв в одну выплату, если нет блокировок. Спор и запрос отмены останавливают её; согласованная двумя организациями отмена освобождает ещё не выплаченный резерв. История сделки / оператора и CSV / JSON реализованы с правами текущих и исторических сторон. Личные уведомления доставляются отдельным worker из outbox после commit, без дублей; прочитанность сохраняется. Следующие этапы — независимый A19, изолированная CLI-демонстрация и проверка на втором ПК. Подключения к платформе Банка России нет.

Добавлена папка исследований: вопросы, шаблоны интервью и командных обсуждений, реестр записей и контекст презентации «ПоАкту». Проведённых интервью пока нет.

Этап уведомлений: полный Go с PostgreSQL / vet / сборка, **71 frontend unit**, оба typecheck / build, OpenAPI 0.7.0 с **37 операциями** и focused API / UI — **17 PASS**. Полный набор — **148 E2E PASS за 6,5 минуты**, после финальной правки автообновления отдельно **9 UI/setup PASS**, smoke после restart и **10 ручных PASS**; окончательный CI фиксируется отдельно в [STATUS.md](docs/STATUS.md) и [отчёте уведомлений](docs/reports/2026-10-24-notifications.md). Уведомления опубликованы поэтапно в [PR #18](https://github.com/Adopten123/digital-ruble-deals/pull/18); merge выполнять после окончательных проверок. История / экспорт и исправление logout уже объединены через PR #16 / #17. Предыдущий [отчёт истории](docs/reports/2026-10-24-deal-history.md) сохраняет 132 E2E и 10 ручных кейсов своего этапа. Команды — в [TESTING.md](docs/TESTING.md), ручные действия — в [MANUAL_TESTING.md](docs/MANUAL_TESTING.md). На текущем ПК Docker Engine ограничен WSL2 / виртуализацией; локальные проверки используют отдельную PostgreSQL, Compose проверяет Linux CI.

MVP показывает собственную логику условного расчёта на тестовых средствах. Цифровой рубль и платформа коммерческих смарт-контрактов (ПКСК) — целевая будущая интеграция.

## Основной сценарий

1. Две компании согласуют стороны, сумму, документ, условия и источник подтверждения.
2. Заказчик резервирует тестовые средства.
3. Имитатор ЭДО присылает проверяемое событие двусторонней подписи.
4. Сервис сверяет сделку, стороны, сумму и конкретную версию документа.
5. При отсутствии спора расчёт исполняется один раз; участники видят результат, доступную историю и личные уведомления.

## Технический задел

По прямому указанию пользователя код и зависимости banking-system не используются. Архитектурный ориентир — [go-todoapp-1](https://github.com/Adopten123/go-todoapp-1): модули, ручная сборка зависимостей и слои HTTP / service / repository. Денежная логика и аутентификация создаются заново.

## Запуск и лицензия

Подготовленная команда локального стенда:

```sh
docker compose up --build
```

Адрес — **http://localhost:8080**. Доступы, альтернативный порт и сохранение данных — в [RUNNING.md](docs/RUNNING.md). Работают документы, согласования, резерв, две тестовые подписи, проверяемая доставка ЭДО / однократная выплата, спор / двусторонняя отмена, учебные счета, история / экспорт и уведомления. Независимый A19, CLI-демонстрация и проверка второго ПК остаются в плане. Команды API / UI — в [TESTING.md](docs/TESTING.md). Лицензия на распространение кода ещё не выбрана; уведомления о PDF-зависимостях и шрифте сохранены в модуле.
