# Новый изолированный демопоказ

25 октября 2026 года. Команда: `poaktu demo create --run-id jury-001 --password-file <файл>`. Тестовый контур. Расчёты и ЭДО эмулируются.

## Результат

Создаются три новых учебных пользователя: заказчик, исполнитель и оператор. У сторон разные организации / счета; оператор остаётся системным и видит учебный контур по прежним общим правам. У заказчика 50 000 000 копеек (500 000 ₽), у исполнителя 0. Средства поступают одной сбалансированной проводкой от DEMO_ISSUANCE. Старые пользователи, счета сторон, документы, резервы и выплаты сохраняются; системный счёт эмиссии отражает новое учебное зачисление.

Четыре сделки создаются обычным service.Create с собственными устойчивыми ключами:

| scenario в JSON | Исходная сумма, коп. | Показ |
| --- | --- | --- |
| payment | 30000000 | Основной расчёт по акту печати |
| dispute | 10000000 | Спор до выплаты |
| cancellation | 5000000 | Два разных согласия на отмену |
| insufficient-funds | 60000000 | Сумма выше начального доступного остатка |

Это DRAFT: PDF, согласия, резерв, подписи, спор / отмена и выплата возникают только после обычных действий участников. Название содержит run-id для поиска. Срок — 14 суток от первого начального зачисления; повтор не продлевает его. Сценарий недостатка средств предполагает отсутствие дополнительных операторских зачислений.

Email: customer.jury-001@demo.poaktu.local, supplier.jury-001@demo.poaktu.local, operator.jury-001@demo.poaktu.local. Для трёх учебных учёток этого показа используется один пароль из входного файла. Значения email / IDs возвращаются JSON-ответом; пароль в нём отсутствует. Открывайте роли в разных профилях браузера: cookie внутри одного профиля общая. Общие быстрые кнопки входа продолжают относиться к прежним bootstrap-учёткам.

## Входные данные и права

run-id обязателен: 3–40 строчных ASCII-букв / цифр / дефисов, первый символ — буква или цифра. Регистр / пробелы автоматически не исправляются. Профиль фиксирован: poaktu-demo-v1. Пароль — 12–128 Unicode-символов, до 512 UTF-8 байт, без управляющих символов. Файл содержит одну строку; один завершающий LF или CRLF допускается, остальные пробелы сохраняются. Нужен обычный файл, а не ссылка / каталог / stdin; ограничение чтения 1024 байта. Пароль не передавайте аргументом командной строки и не добавляйте в Git.

Требуются DEMO_MODE=true, готовые migrate / access / bootstrap, DATABASE_URL владельца **учебной** БД и прежний APP_KEY_FILE. Runtime не может запускать подготовку, HTTP-маршрута сброса / подготовки нет. Команда читает сохранённый APP_KEY, не создаёт новый ключ и не использует приватный ключ A19. Новых миграций / таблиц / HTTP-операций нет: схема остаётся 010, Swagger 0.8.0 — 37 операций.

## Docker Compose

Сначала обычный запуск из [RUNNING.md](RUNNING.md). Дополнительный compose.demo.yaml монтирует только пароль и ключ приложения для чтения, работает владельцем БД во внутренней сети. В serve входной каталог пароля не монтируется. POAKTU_DEMO_INPUT_DIR должен быть абсолютным путём к частному каталогу, доступному UID/GID 10001 контейнера.

Пример на Linux, создание нового файла без перезаписи:

```sh
mkdir -p work
export POAKTU_DEMO_INPUT_DIR="$(pwd)/work/demo-input"
mkdir -m 700 "$POAKTU_DEMO_INPUT_DIR"
(umask 077; set -C; head -c 24 /dev/urandom | base64 > "$POAKTU_DEMO_INPUT_DIR/password.txt")
sudo chgrp 10001 "$POAKTU_DEMO_INPUT_DIR" "$POAKTU_DEMO_INPUT_DIR/password.txt"
chmod 750 "$POAKTU_DEMO_INPUT_DIR"
chmod 640 "$POAKTU_DEMO_INPUT_DIR/password.txt"
docker compose -f compose.yaml -f compose.demo.yaml run --rm --no-deps demo demo create --run-id jury-001 --password-file /input/password.txt
```

Хостовый владелец файла сохраняет доступ; контейнер читает его через свою группу. Просматривайте пароль локально, не отправляйте его в общий лог / отчёт. Для нового показа можно использовать другой частный файл и новый run-id. Не очищайте volumes.

На Windows подготовьте каталог, разрешённый Docker Desktop, и задайте POAKTU_DEMO_INPUT_DIR абсолютным путём. Учтите права общего каталога Windows; числовые POSIX-права выше к NTFS не применяются. Дальнейшая Compose-команда та же.

## Собранный бинарный файл на Windows / PowerShell 7

В текущем процессе уже должны быть настроены DEMO_MODE=true, DATABASE_URL владельца локальной учебной БД и APP_KEY_FILE от bootstrap. Пример создания нового входного файла; CreateNew не заменит существующий пароль:

```powershell
$demoDirectory = Join-Path (Get-Location) 'work/demo-input'
New-Item -ItemType Directory -Path $demoDirectory -Force | Out-Null
$demoPasswordPath = Join-Path $demoDirectory 'password.txt'
$demoPassword = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(24))
$demoFile = [IO.File]::Open($demoPasswordPath, [IO.FileMode]::CreateNew)
try {
    $demoBytes = [Text.Encoding]::UTF8.GetBytes($demoPassword)
    $demoFile.Write($demoBytes, 0, $demoBytes.Length)
} finally { $demoFile.Dispose() }
.\poaktu.exe demo create --run-id jury-001 --password-file $demoPasswordPath
```

Файл храните под доступом своего пользователя. CLI печатает только служебный JSON с исходными учётками / IDs и суммами; он не записывает файл манифеста автоматически. При необходимости сохраняйте stdout в новый файл в work, без подмены исходного пароля. Загрузка PDF не входит в подготовку, DOCUMENTS_DIR команда не создаёт.

## Повтор и прерывание

Начальные учётки / организации / счета, проводка, marker и DEMO_RUN_SEEDED входят в одну PostgreSQL-транзакцию. Marker — строка demo_seed:v1:<run-id>:<HMAC> в bootstrap_runs; HMAC с отдельным доменом связывает исходные run-id / пароль с сохранённым ключом приложения. Открытый пароль и прямой SHA-256 пароля в marker не сохраняются: используется HMAC с ключом приложения. Новые пользователи получают обычные Argon2id-хеши с отдельными солями.

Общая блокировка по run-id сериализует seed. Уникальный ledger operation_key дополнительно запрещает вторую начальную проводку. Черновики затем создаются через существующий сервис отдельными транзакциями. Если процесс прервался после seed или между черновиками, повтор с теми же run-id / паролем / APP_KEY продолжает подготовку: уже сохранённые результаты CREATE_DEAL возвращаются без новой сделки / аудита. DEMO_READY выдаётся только после четырёх сохранённых результатов создания.

resumed=true означает, что начальный seed уже существовал; это не утверждение, что прежняя попытка успела подготовить все черновики. initial_customer_balance_kopecks и initial_amount_kopecks — **исходные** значения. Повтор после оплаты возвращает те же IDs, не сбрасывая SETTLED / CONSUMED / payment_id, фактические остатки, версии PDF, уведомления или историю. Текущее состояние смотрите через обычный API / UI. Уже истёкший срок тоже не продлевается.

Другой пароль / APP_KEY при том же run-id даёт RUN_CONFLICT; существующая посторонняя учётка с нужным email не присваивается показу. Изменённые исходные роли / членства / проводка или конфликт тела создания требуют проверки, а не автоматического ремонта. Если незавершённый seed старше 14 суток и недостающий черновик уже нельзя создать до срока, возвращается RUN_EXPIRED. Для свежего показа выберите новый ID явно; прежний seed остаётся в истории.

| status / code | Exit | Действие |
| --- | --- | --- |
| DEMO_READY | 0 | Исходный набор подготовлен; JSON содержит run-id, seed/deadline, три identities и четыре deals |
| INVALID_ARGUMENT | 2 | Исправить ID / режим create / входной файл |
| RUN_CONFLICT | 2 | Сверить первоначальные пароль / APP_KEY; существующие данные не заменяются |
| RUN_EXPIRED | 2 | Для свежей подготовки явно выбрать новый run-id; старый не удаляется |
| OWNER_REQUIRED | 3 | Использовать подключение владельца учебной БД |
| RUN_CHANGED | 3 | Проверить исходные факты; не восстанавливать их вслепую |
| UNKNOWN_OUTCOME | 3 | Исход commit неизвестен; повторить те же входные данные, не генерировать новый ID автоматически |
| UNAVAILABLE / INCOMPLETE | 3 | Проверить доступность / bootstrap; продолжить с прежними входными данными |

Команда держит общую lease на каждом соединении до его закрытия, включая восстановленные соединения. Независимый Capture A19 не смешивается с её записями. Новый показ закономерно меняет покрытые A19 данные: прежний эталон может дать MISMATCH. CLI не подписывает и не обновляет эталон автоматически. Порядок принятия новой независимой точки — [INTEGRITY.md](INTEGRITY.md).

## Проверки

PostgreSQL-тесты проверяют новые / разные показы, точный повтор без записи, шесть конкурентных повторов, конфликт разных паролей, collision чужого email, rollback при int64-переполнении эмиссии, запрет ограниченной роли и продолжение после двух из четырёх черновиков. Отдельный HTTP-тест выполняет настоящий расчёт, затем повторяет setup: ID расчёта / деньги / аудит сохраняются. UNIT-проверки включают неправильные входы, EOF / пробелы файла и понятный отказ просроченной незавершённой подготовки.

scripts/demo-smoke.mjs в Linux CI запускает отдельные контейнерные процессы CLI и настоящие API / UI: новые / повторные IDs, runtime-отказ, разные стороны, три роли desktop / 375 px, PDF / две реальные тестовые подписи / единственную выплату и повтор bootstrap / CLI после неё. Входной файл частный, в артефакты его не добавляют. После smoke API перезапускается перед общим E2E, чтобы история проверок входа не меняла лимиты следующего набора. Фактически выполненные результаты — в [отчёте](reports/2026-10-25-isolated-demo-run.md).
