# Уведомления внутри приложения

Контракт этапа `feature/in-app-notifications`. Фактические проверки и готовность публикации — в [STATUS.md](STATUS.md). Это часть учебного MVP; реальные сообщения по почте, SMS или мессенджерам не отправляются.

## Сохранённый факт и доставка

Доменная команда сначала атомарно сохраняет результат, аудит и outbox вместе со своими изменениями. Отдельный worker внутри API читает только зафиксированные задания. В одной PostgreSQL-транзакции он блокирует до 50 pending-строк через FOR UPDATE SKIP LOCKED, создаёт уведомления и отмечает delivered_at. Несколько экземпляров не забирают один pending-job одновременно. Ошибка до commit откатывает и уведомления, и ACK; неизвестный результат commit безопасно выясняется следующим чтением / повтором. Отдельного сетевого вызова между вставкой и ACK нет.

Схема 009 добавляет notifications, не переписывает миграции 001–008 и старые факты. При обновлении ранее накопленный outbox доставляется тоже. Поэтому уведомление имеет два разных времени: created_at — фактическая доставка после обновления, event.created_at — исходный факт. Перезапуск и повтор bootstrap не удаляют историю, не сбрасывают прочитанность и не создают второй экземпляр.

Уникальность (event_id, recipient_user_id) защищает повтор задания. Дополнительно (recipient_user_id, semantic_key) объединяет повторное согласие под другим ключом: agreement:<ID сохранённого согласия>. Остальные ключи — event:<ID аудита>. Прежние аудиторские записи команд не удаляются. Уведомление ссылается на аудит, собственного raw payload не хранит. Идентичность / получатель / основание неизменяемы; read_at меняется только один раз из NULL в дату. Outbox разрешает только первое заполнение delivered_at; runtime-права не дают менять содержание / источник задания.

## Какие события получает пользователь

| Событие | Получатели / смысл |
|---|---|
| DEAL_CREATED | Текущие участники сохранённой версии, включая автора |
| AGREE_DEAL | То же, один раз для конкретного согласия организации |
| DEAL_REWORKED | Возврат на доработку и сохранённая причина |
| DEAL_RESERVED | Подтверждение полного учебного резерва |
| DOCUMENT_SIGNED | Каждая отдельная тестовая подпись, включая вторую |
| DEAL_SETTLED | Один сохранённый расчёт; не новое платёжное поручение |
| DISPUTE_OPENED | Открытие спора и блокировка выплаты |
| CANCELLATION_REQUESTED | Запрос второго голоса по отмене |
| CANCELLATION_ACCEPTED | Согласованное завершение / освобождение собственного резерва |
| CANCELLATION_REJECTED | Отказ с причиной; необходимость ручной проверки |
| DEMO_CREDITED / DEMO_DEBITED | Только организация реально затронутого учебного счёта |

Получатели — действующие пользователи / владельцы организаций в момент обработки задания. Для сделки берётся пересечение текущих сторон и сторон именно сохранённой версии. Автор тоже получает подтверждение факта. Системный DEMO_OPERATOR не получает клиентских уведомлений. Новое членство само по себе не создаёт копию уже доставленной истории.

Технический EDO_EVENT_READY не дублирует вторую подпись; PATCH / замена PDF, отказы команд и неизвестные типы не создают пользовательских уведомлений этого этапа. Их задания помечаются обработанными с нулём получателей; факты остаются в аудите. Срок сделки не превращается в вымышленный исторический факт: отдельный планировщик уведомлений о сроке не реализован. Истечение срока по-прежнему не доказывает отсутствие работ и не освобождает резерв.

## Права и данные

Каждое чтение списка, подсчёт и отметка заново проверяют получателя, его действующее членство и доступ к исходному событию. Бывший исполнитель теряет доступ, новый исполнитель не видит прежний раунд. Недоступная строка не попадает в items / unread_count и даёт 404 при отметке. Для глобального учебного движения проверяется собственная организация счёта из сохранённого основания, а не произвольный ID клиента.

Вложенное event использует [безопасный AuditEvent](api/openapi.json): только разрешённые поля исходного факта. Нет raw payload, снимков команд, адресов почты / паролей, cookie, CSRF / HMAC, ключей приложения, внутренних путей и байтов PDF. Текст причины остаётся пользовательскими данными и выводится React как текст. Уведомление не выдаёт новое право на карточку: открытие сделки делает защищённый GET.

## HTTP

GET /api/v1/notifications возвращает `{items:[{id,created_at,read_at,event}],next_cursor,unread_count}`. Query: unread отсутствует — все, true — непрочитанные, false — прочитанные; limit — каноническое целое 1–100 (по умолчанию 20), cursor — непрозрачная строка. Пустые / повторные / неизвестные параметры запрещены. Оператор получает 200 с пустым items, null cursor и нулём непрочитанных.

Порядок — created_at DESC, id DESC по времени доставки. Подписанный курсор связан с пользователем, организацией, фильтром, limit и верхней парой первой страницы. Один запрос читает согласованный SQL-снимок списка / счётчика; между несколькими HTTP-запросами общего MVCC-снимка нет. Новая отметка / потеря доступа может сократить следующую страницу. Для новых доставок нужно начать с первой страницы. unread_count всегда считает все доступные непрочитанные, независимо от фильтра items.

POST /api/v1/notifications/{id}/read требует строго пустое тело, Origin, сессию и CSRF. Idempotency-Key не нужен: повтор возвращает 204 и сохраняет первоначальный read_at. Чужой / неизвестный / утративший доступ ресурс — 404. При потерянном ответе безопасно перечитать список или повторить отметку. X-Expected-User-ID защищает старую вкладку от выполнения под другим аккаунтом. Ошибки — в [OpenAPI](api/openapi.json).

## Интерфейс и границы

В кабинете участника — вкладка «Уведомления», счётчик непрочитанных, фильтр прочитанности, постраничная загрузка, отметка одной строки и переход к доступной сделке. Polling / возвращение фокуса обновляют счётчик без WebSocket. Старые запросы отменяются и проверяют ожидаемую личность; ответы прежнего аккаунта не переносятся в новый кабинет. Интерфейс различает время доставки и факта, важное при обработке старого outbox.

Уведомление сообщает результат, но не меняет деньги, подписи, спор или решение отмены. Ошибка доставки не откатывает уже подтверждённую доменную команду. Это не независимый криптографический контроль администратора БД: A19 остаётся отдельной задачей.
