## Docker Compose

Нужны Docker с работающим Linux Engine и Docker Compose. Go, Node.js и PostgreSQL на компьютере жюри не требуются.

Из корня репозитория:

```sh
docker compose up --build
```

Открыть **http://localhost:8080**. Это канонический origin: `127.0.0.1` и `localhost` различаются при проверке CSRF / Origin. Порт опубликован только на loopback. Web подключён к отдельной bridge-сети ingress; связи web → API и API → БД остаются во внутренних сетях. БД и API наружу не публикуются; `/internal/` не проксируется. Разделение внешней и внутренней сети соответствует [модели Docker Compose](https://docs.docker.com/compose/how-tos/networking/).

Порядок запуска: PostgreSQL healthcheck → migrate → access (ограниченные права роли API) → bootstrap → API readiness → web. Миграции проверяют контрольные суммы; bootstrap не повторяет начальное зачисление и не сбрасывает пароли. БД, ключи и будущие документы сохраняются в named volumes. API и web работают непривилегированными пользователями; ключ доступен API только для чтения.

На компьютере разработки Docker Engine пока не удалось запустить из-за WSL2 / виртуализации; приложение проверено отдельно на локальной PostgreSQL. Предыдущий каркас до черновиков прошёл полный запуск из чистой копии в [Linux CI](https://github.com/Adopten123/digital-ruble-deals/actions/runs/39368496701) на коммите `64a2152`: сборка, readiness, HTTP smoke, повторный bootstrap и перезапуск. Тот же прогон подтвердил Go race-тесты с PostgreSQL 18.6. Для черновиков CI дополнен проверкой прежнего ID / ключа после перезапуска; его актуальный результат смотреть в pull request этого этапа. Проверка на втором пользовательском ПК остаётся в плане.

## Документация API и frontend

На запущенном web открыть `/api-docs/` (Compose: `http://localhost:8080/api-docs/`). Swagger UI и OpenAPI входят в локальную сборку, CDN не требуется. Экспорт схемы — `/api-docs/openapi.json`; исходник — [api/openapi.json](api/openapi.json). Порядок работы с cookie / CSRF и полный справочник текущих операций — [api/README.md](api/README.md). Устройство интерфейса, dev proxy, восстановление команд и команды разработки — [FRONTEND.md](FRONTEND.md).

`npm --prefix web run docs:check` проверяет OpenAPI и совпадение операций с Go. Перед dev / dev:e2e / build автоматически выполняется docs:prepare; после изменения схемы на уже запущенном Vite можно вызвать `npm --prefix web run docs:prepare`. При первом добавлении public-папки требуется перезапуск старого Vite. Сам backend не раздаёт Swagger, открывать его следует через web origin.

## Учебные учётные записи

Общий публичный пароль стенда: `PoaktuDemo2026!`.

| Email | Назначение | Начальный общий остаток |
|---|---|---:|
| customer@demo.poaktu.local | Владелец организации заказчика | 500 000 ₽ |
| supplier@demo.poaktu.local | Владелец организации типографии | 0 ₽ |
| operator@demo.poaktu.local | DEMO_OPERATOR, без организации | Нет клиентского счёта |

Новая регистрация создаёт отдельную учебную организацию и счёт с нулём. Название компании не даёт членства в существующей организации. Панель денежных действий оператора пока отсутствует. Начальные 50 000 000 копеек записываются двумя сбалансированными проводками с отдельным системным противосчётом; реальных денег нет.

Пароли и подключения выше — намеренно публичные данные локального демо, не производственные секреты. Приложение требует `DEMO_MODE=true`. HMAC-ключ CSRF / курсоров генерируется при bootstrap, хранится в volume и не входит в Git / образ. Подключать реальные счета, документы или производственную БД запрещено.

## Проверка состояния и повторный запуск

```sh
docker compose ps --all
docker compose logs --tail 100 api
docker compose run --rm bootstrap
docker compose restart api web
```

`GET /healthz` показывает работоспособность процесса, `GET /readyz` — доступность БД, схемы и завершённого bootstrap. Readiness возвращает `stage: "deal_drafts"`; это готовность создания / чтения черновиков, не платёжного MVP.

Повторный bootstrap сохраняет прежние данные. CLI создания нового изолированного сценария будет добавлена на этапе денежного ядра; разрушительного HTTP reset нет.

Остановка с сохранением данных:

```sh
docker compose down
```

Команды удаления volumes не нужны для обычного запуска. Не удалять историю, чтобы повторить показ.

Если 8080 занят, в PowerShell задать **оба** значения и пересоздать стенд:

```powershell
$env:POAKTU_PORT = '8082'
$env:POAKTU_ORIGIN = 'http://localhost:8082'
docker compose up --build
```

## Проверки кода и API

Для разработки нужны Go 1.27.2 и Node.js 22 (проверено локально на 22.19.0, в контейнере закреплена 22.23.3).

```sh
go vet ./...
go test ./... -count=1
go build ./cmd/poaktu
npm --prefix web ci --ignore-scripts
npm --prefix web run typecheck
npm --prefix web test
npm --prefix web run build
```

Без `TEST_DATABASE_URL` PostgreSQL-тесты пропускаются. Для их выполнения использовать отдельную учебную БД; каждый тест создаёт случайную схему и удаляет только её. Пример DSN: `postgres://poaktu_test:local_test_password@127.0.0.1:55439/poaktu_foundation_test?sslmode=disable`. Не задавать production DSN. В CI выполняется также `go test -race` на Linux.

Для запущенного стенда и Node.js:

```sh
node scripts/smoke.mjs
```

Smoke создаёт синтетическую организацию с нулём и два черновика, проверяет роли / CSRF / каталог / остатки, создание / повторы / конфликт / конкурентность и доступ к списку / карточке, затем отзывает свои сессии. Он не сбрасывает БД и не переводит деньги. `SMOKE_STATE_FILE` задаёт файл с ID / ключом / телом учебного запроса без сессий и паролей: при следующем запуске smoke проверяет прежний черновик и результат ключа после перезапуска. В CI файл находится во временной папке runner. По умолчанию цель — loopback `http://localhost:8080`; для dev API можно задать `BASE_URL` и точный браузерный `APP_ORIGIN`.

При разработке вне Docker сначала создать отдельную БД, задать `DATABASE_URL`, `DEMO_MODE=true`, `APP_ORIGIN`, `APP_KEY_FILE` и `MIGRATIONS_DIR`, затем выполнить `poaktu migrate`, `poaktu bootstrap`, `poaktu serve`. Vite использует proxy на `127.0.0.1:8081`; для него `HTTP_ADDR=127.0.0.1:8081`, `APP_ORIGIN=http://localhost:5173` и `npm --prefix web run dev`. БД / ключи / SDK / зависимости в репозиторий не коммитятся.

### Комплексные проверки Playwright

Пошаговый самостоятельный прогон, включая проверку наложений и ошибок, — в [MANUAL_TESTING.md](MANUAL_TESTING.md).

Для изолированного запущенного стенда задать `E2E_BASE_URL` (например, `http://localhost:8080`); `E2E_API_URL` по умолчанию совпадает с ним. Из папки `web`:

```sh
npm run typecheck:e2e
npx --no-install playwright install chromium
npm run test:e2e
```

Только настоящий API, без установки браузера: `npm run test:api`. Полный набор уже включает API. Команды запускать последовательно: авторизованные состояния и отчёты общие. По умолчанию E2E ожидает изолированный стенд на 18080; пример Compose с отдельным именем проекта, защитные проверки адреса, синтетические данные, лимиты auth и покрытие A01–A20 описаны в [TESTING.md](TESTING.md). Весь набор из 51 проверки, включая layout-матрицу, прошёл локально и в [Linux CI](https://github.com/Adopten123/digital-ruble-deals/actions/runs/39575716833) на собранном Compose-приложении через nginx.

## Состав и версии

Backend: Go 1.27.2, pgx 5.11.0, x/crypto 0.58.0. Frontend: React 19.3.1, TypeScript 7.0.2, Vite 8.3.4; точные транзитивные зависимости — в lock-файле. Контейнеры: Go 1.27.2, Node 22.23.3, PostgreSQL 18.6, nginx 1.30.6, Alpine 3.24.2; Dockerfile / Compose закрепляют также digest образов. Локальные интеграционные проверки использовали установленную PostgreSQL 18.1 в новом отдельном кластере.

Структура: `cmd/poaktu` собирает config / PostgreSQL / repositories / services / handlers; `internal/core` содержит общую инфраструктуру; `internal/features` — auth, organizations, bootstrap и deals. Миграция 001 содержит основу, 002 — черновики / версии / результаты команд / аудит / pending outbox. Полного платёжного реестра пока нет. После публикации применённые миграции не редактировать: добавлять следующую.

Обычная роль API имеет SELECT и ограниченные INSERT / UPDATE для идентификации и нулевых счетов, INSERT черновика, условий, результата команды, аудита и outbox. Она не может явно задать состояние / версию / дату резерва сделки или дату доставки outbox. DDL, bootstrap, создание оператора, изменение остатков и запись проводок ей не выданы. Расширение денежных прав должно сопровождать реализацию соответствующих операций и тестов.
