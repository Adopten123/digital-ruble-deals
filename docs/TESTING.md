# Проверки UI и API «ПоАкту»

Обновлено: 21 октября 2026 года. Проверяется реализованный этап: авторизация, организации и черновики сделок. Резервы, PDF, согласование, подписи, ЭДО, выплаты, споры, отмена, экспорт и обнаружение вмешательства ещё не реализованы; зелёный результат текущего набора не подтверждает готовность всего [ТЗ](TZ.md).

## Фактический результат

21 октября единый локальный запуск Playwright завершился результатом **47 passed за 25,8 с**: 26 API-тестов, 20 UI-тестов и подготовка сессий. Запуск использовал настоящий Go API и отдельную учебную PostgreSQL 18.1 вне Docker. Chromium проверял desktop 1440 × 1000 и мобильный viewport 375 × 812, локаль `ru-RU`, часовой пояс `Europe/Moscow`. Мобильный проект — эмуляция viewport и touch в Chromium, не проверка физического телефона или Safari.

Дополнительно 21 октября прошли frontend typecheck, 16 Node-тестов, production build, `typecheck:e2e`, `go vet ./...` и `go test ./... -count=1` с `TEST_DATABASE_URL` отдельной PostgreSQL 18.1.

Тесты опубликованы в [PR #6](https://github.com/Adopten123/digital-ruble-deals/pull/6). [Новый запуск Linux CI](https://github.com/Adopten123/digital-ruble-deals/actions/runs/39544562632) на момент записи выполняется, его успешный результат пока не подтверждён. Предыдущие проверки Compose и Go сохраняются в [STATUS.md](STATUS.md); они не заменяют результат CI новой ветки.

## Уровни проверок

| Набор | Что проверяет | Данные / среда |
|---|---|---|
| Go unit / integration | Валидацию, пароли / сессии, транзакции, ограничения БД, bootstrap, атомарность черновика / результата команды / аудита / outbox, конкурентные повторы | Настоящая PostgreSQL при заданном `TEST_DATABASE_URL`; отдельная случайная схема на тест |
| Node unit | Точные денежные преобразования, API-клиент, сохранение команды неизвестного исхода, даты / курсоры | Функции frontend; локальный подставной transport там, где проверяется сам клиент |
| Playwright API | Реальные HTTP-маршруты, серверные права, cookie / CSRF, протокол, сохранённые результаты и поиск | Запущенный API и PostgreSQL, без подмены ответов |
| Playwright UI | Формы, переходы, реальную регистрацию / создание / чтение, восстановление после сбоев, desktop / mobile | Chromium и тот же API; явные сбои вводятся перехватом отдельных запросов |
| HTTP smoke | Готовность опубликованного стенда, основной контракт, повторный bootstrap и сохранение черновика / ключа после перезапуска | Compose или локальный API; инструкция в [RUNNING.md](RUNNING.md) |

В UI успешные ответы не подменяются. Перехват используется для явно заданных `401`, `503`, обрыва сети, задержки и окончательного отказа валидации. После снятия сбоя повтор обращается к настоящему серверу. Особенно важный сценарий: `route.fetch()` сначала получает настоящий `201` и ID сохранённого черновика, затем ответ браузеру обрывается. После reload интерфейс восстанавливает условия и ключ; ручной повтор отправляет прежнее тело / ключ, а серверный список содержит ровно прежний ID.

## Подготовка изолированного стенда

Нужны Node.js 22 и работающий тестовый стенд из [RUNNING.md](RUNNING.md). Compose-проект для тестов должен иметь отдельное имя, порт и named volumes, чтобы синтетические записи не попадали в демонстрацию пользователя. Пример PowerShell из корня репозитория:

```powershell
$env:POAKTU_PORT = '18080'
$env:POAKTU_ORIGIN = 'http://localhost:18080'
docker compose -p poaktu-e2e up --build --wait --wait-timeout 180
$env:E2E_BASE_URL = 'http://localhost:18080'
$env:E2E_API_URL = $env:E2E_BASE_URL
Set-Location web
npm ci --ignore-scripts
npm run typecheck:e2e
```

Стенд на стандартном порту 8080 тоже подходит: установить `E2E_BASE_URL=http://localhost:8080` и такое же `E2E_API_URL`; его `POAKTU_ORIGIN` должен совпадать. Не подменять `localhost` на `127.0.0.1` только в одном из значений: cookie / проверка Origin должны соответствовать реальному подключению.

Зависимость `@playwright/test` закреплена как **1.64.1** в `web/package.json` и lock-файле. Для полного набора установить соответствующий Chromium из папки `web`:

```sh
npx --no-install playwright install chromium
npm run test:e2e
```

На Linux для установки браузера вместе с системными библиотеками используется `npx --no-install playwright install --with-deps chromium`. API-проект браузер не запускает и скачивания Chromium не требует:

```sh
npm run test:api
```

Выбрать один нужный запуск. `test:e2e` уже включает API, desktop, mobile и setup. Отдельные команды Playwright запускать последовательно: они используют общие `actors.json`, состояния сессий, папки результатов и HTML-отчёт. Параллельные независимые процессы CLI могут перезаписать эти файлы.

Конфигурация использует одного worker, без автоматических повторов упавшего теста. Сессии четырёх ролей подготавливаются один раз на запуск и затем переиспользуются. Серверные ограничители не отключаются: 30 auth-запросов с одного IP в минуту, 10 на email в минуту и ограничение одновременно проверяемых паролей. Несколько быстрых прогонов подряд могут исчерпать лимит; дождаться следующей минуты или перезапустить только API своего изолированного тестового стенда. Не перезапускать чужую демонстрацию ради тестов.

Для разработки без Docker предусмотрен `npm run dev:e2e`: Vite слушает `127.0.0.1:18080` и проксирует API на `127.0.0.1:18081`. Такой API запускать с отдельной учебной БД, `HTTP_ADDR=127.0.0.1:18081`, `APP_ORIGIN=http://localhost:18080`, отдельным файлом ключа и обычными migrate / bootstrap из RUNNING.md. Этот режим не занимает порты демонстрации 5173 / 8081.

## Границы и результаты запуска

`E2E_BASE_URL` по умолчанию равен `http://localhost:18080`; `E2E_API_URL` по умолчанию совпадает с ним. Отдельный API-origin допускается только с тем же hostname, чтобы состояния cookie работали и в UI. Адреса ограничены HTTP(S) loopback без credentials, пути, query и hash. Setup требует успешный `/readyz` с `contour: "test"` и `stage: "deal_drafts"`. Это защита от ошибочного адреса, а не автоматическое создание или изоляция БД: стенд нужно подготовить отдельно.

Тесты создают синтетические организации и черновики с уникальными ID / названиями. Они не очищают БД, не выполняют переводы, не удаляют историю и не изменяют существующие условия. Поэтому записи на выбранном учебном стенде сохраняются после запуска. Для остановки изолированного Compose-проекта с сохранением данных:

```sh
docker compose -p poaktu-e2e down
```

Удаление volumes не требуется. Следующий запуск может использовать сохранённый учебный стенд.

Артефакты находятся в:

- `web/playwright-report/` — HTML-отчёт;
- `web/test-results/artifacts/` — результаты, снимки и trace при сбое;
- `web/test-results/auth/` — приватные cookie-состояния ролей и `actors.json`.

Все эти папки исключены из Git. Состояния авторизации содержат действующие учебные сессии; их не прикладывать к публичным отчётам. При передаче trace / снимков учитывать, что они могут содержать временные cookie, синтетические email, тела команд и данные выбранного тестового стенда. CI загружает только HTML-отчёт и папку `artifacts`, без `auth`, хранит результат семь дней и останавливает свой контур в шаге `always()`.

## Покрытие реализованного этапа

| Область | API | UI |
|---|---|---|
| Авторизация | Анонимная / поддельная сессия, серверные роли / срок, одинаковый отказ для неверного пароля / неизвестного email, запрет роли из регистрации, нулевой счёт, ротация и отзыв украденной cookie | Ошибка входа с восстановлением, регистрация COMPANY / IP, повтор email, reload / logout, Unicode-пароль до 128 и название до 200 символов, сбой bootstrap / readiness и возвращение к входу при `401` |
| Каталог / счёт | Только публичные поля, own scope, три точных остатка, оператор без счёта, поиск, пустой результат, пагинация и подпись курсора | Три остатка, поиск / пустой результат, отметка своей организации, сетевой сбой / повтор, оператор без управления счётом / сделками |
| Черновики | Точное сохранение, чтение сторонами, сокрытие от третьей организации / оператора, отсутствие изменения счетов, MaxInt64, строки Unicode, стороны / валюта / срок | Создание из формы, точные копейки выше безопасного диапазона Number, UTC, карточка / список и кабинет исполнителя, исключение себя из выбора, локальная валидация |
| Повторы / сбои | Сохранённый результат и конфликт тела, область организации, нормализация, 8 конкурентных повторов, сохранённый семантический отказ | Потеря ответа после commit + reload / повтор, блокировка условий, двойной клик, `503` с тем же ключом, новый ключ после окончательного отказа, повреждённая сохранённая команда |
| Поиск / состояния | Роли, даты, сортировка / пагинация, подписанные курсоры и привязка к фильтрам, инъекционные строки, истёкший срок и исторический POST-ответ | Фильтры / сброс / некорректный период, 21 запись без дублей на двух страницах, повтор после сбоя, защита от ответа уже закрытого представления |
| HTTP / отображение | `/healthz` / `/readyz`, request ID / заголовки, CSRF / Origin / чужой токен, строгий JSON / UTF-8 / типы, `413` / `415`, ключи, недоступность внутренних маршрутов | Мобильная геометрия 375 px, читаемая карточка / форма, Enter для поиска, отсутствие горизонтального переполнения и проверяемых ошибок браузера |

При тестировании обнаружено и исправлено расхождение Unicode: HTML `maxLength` считал UTF-16, тогда как сервер считает символы Unicode. Форма теперь допускает документированные пределы пароля / названия и локально отклоняет превышение; пограничная регистрация проверяется настоящим API.

## Связь с критериями A01–A20

«Проверяется сейчас» относится к существующим функциям, а не к готовности всего прототипа. Будущие сценарии не добавлены как фиктивно проходящие или пропущенные тесты.

| Критерий | Статус текущего покрытия | Что ещё требуется |
|---|---|---|
| A01 — чистый Compose | Частично: предыдущий каркас прошёл Linux CI; текущие E2E прошли локально вне Docker | Новый E2E-набор в CI и чистый запуск на втором пользовательском ПК |
| A02 — регистрация / вход / выход | Проверяется сейчас Go + API + UI: нулевой счёт, хеш, сессия / отзыв | Повторять проверки при изменениях авторизации |
| A03 — чужие ресурсы / подмена роли | Частично: организации, каталог, сделки и подмена входных ID / роли | Права на PDF, историю и экспорт после реализации |
| A04 — изменение условий / PDF | Будущий этап | Новая версия, сброс действующих согласий, невозможность использовать старые факты |
| A05 — резерв / недостаток средств | Будущий этап; три начальных остатка уже проверяются | Реальный резерв и отказ без денежных изменений |
| A06 — денежные гонки | Будущий этап | Конкурирующие резервы / списания, отсутствие отрицательного available |
| A07 — ключ / конфликт тела | Частично: создание черновика, успех / отказ / конкурентные повторы | Остальные изменяющие команды |
| A08 — PDF / одна подпись | Будущий этап | Допустимость файла, предел 5 MiB, отсутствие выплаты от одной подписи |
| A09 — единственная выплата | Будущий этап | Две подписи, событие, проводки и правильные остатки |
| A10 — источник / привязки ЭДО | Будущий этап | Неверные источник, стороны, сумма, валюта, версии и хеш |
| A11 — повторы событий | Будущий этап | Inbox, параллельная доставка, конфликт payload и одна выплата |
| A12 — спор / гонка с выплатой | Будущий этап | Атомарная блокировка расчёта спором |
| A13 — согласованная отмена | Будущий этап | Два разных голоса, однократное освобождение, гонка с выплатой |
| A14 — срок / отказ отмены | Частично: истёкший DRAFT читается и фильтруется как REVIEW_REQUIRED | Отказ отмены и срок профинансированной сделки без автоматического движения денег |
| A15 — несколько сделок / поиск / история | Частично: несколько черновиков, scope, поиск / фильтры / пагинация | Уведомления и экспорт истории CSV / JSON без дублей |
| A16 — перезапуск после денежных операций | Будущий этап; прежний smoke уже проверяет сохранение черновика / ключа | Сохранение резерва, подписей, проводок и inbox; отсутствие второй выплаты |
| A17 — права оператора | Частично: роль недоступна регистрации, оператор отделён от организации / сделок | Денежная панель и невозможность обхода условий расчёта |
| A18 — сбой / потеря ответа | Частично: rollback черновика, `503`, потеря ответа после commit и повтор | Повтор доставки событий и уведомления после commit |
| A19 — обнаружение вмешательства | Будущий этап | Независимый эталон, проверяющий и атаки на изолированные копии; SQL-неизменяемость аудита сама по себе этого не доказывает |
| A20 — возврат на доработку | Будущий этап | AGREED → новая DRAFT, PDF / согласия, повторы и гонка с резервом |

Дальнейшие тесты добавлять вместе с реализацией соответствующих маршрутов по [API.md](API.md), [STATE_MACHINE.md](STATE_MACHINE.md) и [DATA_MODEL.md](DATA_MODEL.md).
