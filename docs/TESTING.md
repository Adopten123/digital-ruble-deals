В UI успешные ответы не подменяются. Перехват используется для явно заданных `401`, `503`, обрыва сети, задержки и окончательного отказа валидации. После снятия сбоя повтор обращается к настоящему серверу. Особенно важный сценарий: `route.fetch()` сначала получает настоящий `201` и ID сохранённого черновика, затем ответ браузеру обрывается. После reload интерфейс восстанавливает условия и ключ; ручной повтор отправляет прежнее тело / ключ, а серверный список содержит ровно прежний ID.

## Подготовка изолированного стенда

Нужны Node.js 22 и работающий тестовый стенд из [RUNNING.md](RUNNING.md). Compose-проект для тестов должен иметь отдельное имя, порт и named volumes, чтобы синтетические записи не попадали в демонстрацию пользователя. Пример PowerShell из корня репозитория:

```powershell
$env:POAKTU_PORT = '18080'
$env:POAKTU_ORIGIN = 'http://localhost:18080'
docker compose -p poaktu-e2e up --build --wait --wait-timeout 180
$env:E2E_BASE_URL = 'http://localhost:18080'
$env:E2E_API_URL = $env:E2E_BASE_URL
Set-Location web
npm ci --ignore-scripts
npm run typecheck:e2e
```

Стенд на стандартном порту 8080 тоже подходит: установить `E2E_BASE_URL=http://localhost:8080` и такое же `E2E_API_URL`; его `POAKTU_ORIGIN` должен совпадать. Не подменять `localhost` на `127.0.0.1` только в одном из значений: cookie / проверка Origin должны соответствовать реальному подключению.

Зависимость `@playwright/test` закреплена как **1.64.1** в `web/package.json` и lock-файле. Для полного набора установить соответствующий Chromium из папки `web`:

```sh
npx --no-install playwright install chromium
npm run test:e2e
```

На Linux для установки браузера вместе с системными библиотеками используется `npx --no-install playwright install --with-deps chromium`. API-проект браузер не запускает и скачивания Chromium не требует:

```sh
npm run test:api
```

Выбрать один нужный запуск. `test:e2e` уже включает API, desktop, mobile и setup. Отдельные команды Playwright запускать последовательно: они используют общие `actors.json`, состояния сессий, папки результатов и HTML-отчёт. Параллельные независимые процессы CLI могут перезаписать эти файлы.

Конфигурация использует одного worker, без автоматических повторов упавшего теста. Сессии четырёх ролей подготавливаются один раз на запуск и затем переиспользуются. Серверные ограничители не отключаются: 30 auth-запросов с одного IP в минуту, 10 на email в минуту и ограничение одновременно проверяемых паролей. Несколько быстрых прогонов подряд могут исчерпать лимит; дождаться следующей минуты или перезапустить только API своего изолированного тестового стенда. Не перезапускать чужую демонстрацию ради тестов.

Для разработки без Docker предусмотрен `npm run dev:e2e`: Vite слушает `127.0.0.1:18080` и проксирует API на `127.0.0.1:18081`. Такой API запускать с отдельной учебной БД, `HTTP_ADDR=127.0.0.1:18081`, `APP_ORIGIN=http://localhost:18080`, отдельным файлом ключа и обычными migrate / bootstrap из RUNNING.md. Этот режим не занимает порты демонстрации 5173 / 8081.

## Границы и результаты запуска

`E2E_BASE_URL` по умолчанию равен `http://localhost:18080`; `E2E_API_URL` по умолчанию совпадает с ним. Отдельный API-origin допускается только с тем же hostname, чтобы состояния cookie работали и в UI. Адреса ограничены HTTP(S) loopback без credentials, пути, query и hash. Setup требует успешный `/readyz` с `contour: "test"` и `stage: "deal_drafts"`. Это защита от ошибочного адреса, а не автоматическое создание или изоляция БД: стенд нужно подготовить отдельно.

Тесты создают синтетические организации и черновики с уникальными ID / названиями. Они не очищают БД, не выполняют переводы, не удаляют историю и не изменяют существующие условия. Поэтому записи на выбранном учебном стенде сохраняются после запуска. Для остановки изолированного Compose-проекта с сохранением данных:

```sh
docker compose -p poaktu-e2e down
```

Удаление volumes не требуется. Следующий запуск может использовать сохранённый учебный стенд.

Артефакты находятся в:

- `web/playwright-report/` — HTML-отчёт;
- `web/test-results/artifacts/` — результаты, снимки и trace при сбое;
- `web/test-results/auth/` — приватные cookie-состояния ролей и `actors.json`.

Все эти папки исключены из Git. Состояния авторизации содержат действующие учебные сессии; их не прикладывать к публичным отчётам. При передаче trace / снимков учитывать, что они могут содержать временные cookie, синтетические email, тела команд и данные выбранного тестового стенда. CI загружает только HTML-отчёт и папку `artifacts`, без `auth`, хранит результат семь дней и останавливает свой контур в шаге `always()`.

Резерв / операторские деньги: Go дополнительно проверяет атомарность фактов, точные версии / PDF, срок после account lock, runtime-права и TEMP-подмену; API — гонки реальных команд и отсутствие двойных резервов; UI — FUNDED обеим сторонам, свежие остатки, прежний ключ после потери ответа, credit/debit / поиск / пагинацию. ## Связь с критериями A01–A20

«Проверяется сейчас» относится к существующим функциям, а не к готовности всего прототипа. Будущие сценарии не добавлены как фиктивно проходящие или пропущенные тесты.

| Критерий | Статус текущего покрытия | Что ещё требуется |
|---|---|---|
| A01 — чистый Compose | Частично: 103 E2E локально и в Linux CI на b86ffd9 через чистый Compose, bootstrap / restart smoke успешны | Чистый запуск на втором пользовательском ПК |
| A02 — регистрация / вход / выход | Проверяется сейчас Go + API + UI: нулевой счёт, хеш, сессия / отзыв | Повторять проверки при изменениях авторизации |
| A03 — чужие ресурсы / подмена роли | Частично: организации, каталог, сделки, текущие / исторические PDF, прежний и новый исполнитель, подмена ID / роли | Права на экспорт после реализации |
| A04 — изменение условий / PDF | Новые версии, сброс согласий, старый replay без реактивации, запрет после резерва; старый PDF нельзя подписать | Повторять при изменении привязок |
| A05 — резерв / недостаток средств | Проверяется Go / API / UI: полный ACTIVE-резерв, недостаток, неизменность total, сохранённый отказ и новый ключ после пополнения | Выплата / освобождение следующими этапами |

| A07 — ключ / конфликт тела | Создание / изменение / PDF / согласие / rework / подпись, резерв и credit/debit, успех / отказ / конкурентные повторы, операторский scope | Добавить доставку ЭДО / выплаты |
