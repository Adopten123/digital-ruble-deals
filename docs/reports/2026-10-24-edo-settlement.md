Это продолжение MVP на учебных средствах, без подключения к платформе Банка России и реального оператора ЭДО.

## Реализовано

После двух сохранённых подписей устойчивое основание доставляется настоящим внутренним HTTP sender с HMAC. Приёмник проверяет источник / время / точные байты, сохраняет durable inbox и сверяет все привязки с фактами сделки. Одна транзакция связывает settlement, две проводки, погашение собственного резерва, SETTLED, окончательный ответ inbox, аудит и outbox. Повтор / новый корректный event ID не создаёт второй выплаты; тот же ID с другим телом конфликтует.

Спор и активная отмена блокируют выплату. Отказ в отмене сохраняет REVIEW_REQUIRED; новый запрос не возобновляет её. Принятие другой организацией освобождает собственный резерв (REFUNDED / RELEASED), без резерва — CANCELLED. Срок не освобождает средства и не мешает второй стороне согласовать отмену. Интерфейс сохраняет исходные команды / ключи при неизвестном исходе и различает очередь, доставку и результат расчёта.

Миграции 001–006 не изменены. 007 / 008 добавляются поверх них; checksum уже применённой 008 сохранён, включая завершающую пустую строку. При штатном обновлении прежние READY_TO_SETTLE могут исполниться после запуска worker, что описано в RUNNING.md.
